## 2. Batch B Status — Security, Testing & Infrastructure Hardening (Complete)

- **Helmet & CORS Hardening**:
  - Configured `Helmet` middleware with customized Content Security Policies (CSP), Cross-Origin Embedder Policies (COEP) tuned to allow fair-use external OG images, and Referrer Policies.
  - Restricted CORS to explicit origins parsed from the environment (`CORS_ALLOWED_ORIGINS`).
  - Documented setup and ssh tunnel access guidelines in `docs/runbooks/security.md`.
- **Admin Authentication Middleware**: Centralized API key checking into `requireAdminKey` middleware (`apps/api/src/middleware/admin-auth.ts`). Applied it across `/api/admin/*` endpoints and the `POST /api/supporters` registration endpoint.
- **Input Sanitization**: Installed `isomorphic-dompurify` and created a central sanitization utility (`apps/api/src/lib/sanitize.ts`). Integrated it to sanitize user-supplied HTML text before PostgreSQL database inserts (`POST /api/submissions`, `POST /api/supporters`).
- **Secret Leak Prevention**:
  - Configured `secretlint` (`.secretlintrc.json`, `.secretlintignore`, and package scripts) for repository-wide credential scans.
  - Scrubbed database connection string fallbacks, webhook tokens, and placeholder keys from all codebase locations, including migration scripts (`scripts/lib/db.ts`), database configs (`apps/api/src/lib/db.ts`), seeders (`workers/ingest/src/seed-new-feeds.ts`), and legacy Python modules.
- **Log Sanitization**: Implemented a custom `logger` module (`apps/api/src/lib/logger.ts`) that automatically masks IP addresses, client emails, full query parameter strings, database connection credentials, and API keys. Replaced all direct `console.*` calls in the API codebase.
- **Integration Tests**:
  - Configured `Vitest` and `Supertest` in `apps/api`.
  - Added 18 integration tests covering rate limits, redirect tracking hashes, supporters tiers, admin authentication, newsletter subscriptions, and public submissions (validating DOMPurify XSS defenses).
  - All 18 tests pass with **100% success rate**.
- **Conventional Commits & Git Hygiene**:
  - Installed and configured `husky` and `commitlint`.
  - Enabled commit hooks: `pre-commit` (runs TypeScript check and `secretlint`) and `commit-msg` (enforces conventional commit standards).
- **Docker Compose Production Hardening**:
  - Implemented limits on resources (`mem_limit: 2g` for database, `1g` for search, `256m` for redis/workers) and restart policies (`unless-stopped`).
  - Restricted json-file logging outputs to a maximum of 10MB per file with a retention of 5 rotated files.
  - Configured database initialization arguments to enforce page-level data checksums (`POSTGRES_INITDB_ARGS: "--data-checksums"`).
  - Enforced internal-network-only security: removed host-exposed ports for PostgreSQL (`almanac-db` on port 5432) and Redis (`almanac-redis` on port 6379), restricting them strictly to the internal Docker network. Only Meilisearch (`almanac-search` on port 7700) remains exposed to the host for reverse proxy integration.
  - Deployed, recreated containers, and validated all compose services as healthy on `chantecler-01`.
